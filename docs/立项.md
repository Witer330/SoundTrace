# 声迹 SoundTrace · 立项章程

## 1. 背景与痛点

每次开会用手机录音（单条 60~180 分钟），带来两个问题：

1. **存储失控**：录音文件逐渐占满手机存储；
2. **复盘低效**：风险规避有了，但回听只能反复拖动进度条，180 分钟的录音定位一句话要几分钟。

## 2. 定位与目标

**一句话**：导入手机录音 → 本地离线转写 → 点字跳音频 → 全文检索 → AI 会议纪要。

**目标用户**：本人（Windows 桌面，单机使用）。

**成功标准**：
- 手机里的录音可安全归档到电脑并去重管理；
- 180 分钟录音本地转写完成（CPU，预期 22~40 分钟），转写稿点字即跳音频；
- 搜索任意关键词秒级列出命中片段；
- 一键生成会议纪要（摘要 / 行动项 / 关键决议）。

## 3. 范围边界

### V1 做

| 模块 | 内容 |
|---|---|
| 导入归档 | 拖拽 / 选文件夹导入；xxhash 内容去重；按年月归档；amr/3gp 自动转码 m4a 副本 |
| 元数据 | 标题、录制时间（ffprobe）、时长、大小、标签、参会人、笔记 |
| 播放器 | 预计算峰值波形（Canvas）、播放/暂停/快进快退、0.5~3x 倍速、书签 |
| 转写 | 模型管理器（下载 + 进度）、后台任务队列（进度/取消/断点续跑）、Paraformer + silero-VAD + CT-Transformer 标点 |
| 转写稿 | 虚拟滚动、点字跳音频、跟随播放滚动、稿内搜索高亮 |
| 检索 | 全局搜索：标题/标签/转写全文（子串匹配，符合中文习惯） |
| AI 复盘 | OpenAI 兼容 API 生成纪要 / 行动项 / 关键决议，Markdown 存储，可重新生成 |
| 导出 | Markdown 纪要 / SRT 字幕 / TXT |
| 设置 | 数据目录、模型管理、LLM 配置（Base URL / Key / Model / 测试连通） |

### V1 不做（明确出界）

- **说话人分离**（V2）：sherpa-onnx + pyannote-segmentation-3.0 + 3D-Speaker CAM++，`segments.speaker` 字段已预留；
- **MTP 手机直连**：用"文件传输到收件夹目录 + 导入"代替；
- **云同步 / 多端 / 多用户**：单机单用户工具；
- **音频编辑**：不裁剪不合成，只读管理；
- **本地 LLM**：复盘只用云端 API（文本出网可接受，录音不出网）；
- **GPU 转写**（V2 可选）：Windows 下 sherpa-onnx CUDA 无官方预编译；备选 FunASR runtime-llamacpp CUDA sidecar。

## 4. 核心技术决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 转写引擎 | sherpa-onnx 官方 Rust crate（v1.13.8+，静态链接） | FunASR/3D-Speaker 是 Python 工具包无法嵌入 Tauri；其模型均有 ONNX 导出，sherpa-onnx 全覆盖（ASR/VAD/标点/后续分离） |
| ASR 模型 | `paraformer-zh-2023-09-14`（int8, 232MB） | 唯一带字符级时间戳的 Paraformer 导出，点字跳转体验最佳；中文准确率优于 Whisper 同级 |
| VAD | silero-vad（非 FSMN-VAD） | sherpa-onnx 官方仅支持 silero/ten，对中文会议效果好 |
| 搜索 | SQLite LIKE 子串 | 中文无分词场景下子串即用户预期；数据量（万级片段）LIKE 足够快 |
| 波形 | Rust 端 ffmpeg 预计算峰值 + Canvas 自绘 | 3 小时音频若浏览器解码 AudioBuffer 需数 GB 内存，预计算峰值 ~200KB 搞定 |
| 任务队列 | 独立工作线程 + Tauri 事件推送进度 | 转写是 CPU 密集长任务，与 UI 解耦，可取消可恢复 |
